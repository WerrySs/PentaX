# Public JSON failure attribution

An actual failure inside an admitted public JSON body may populate the existing
`public_function` diagnostic. Labels are fixed public function names from
[the pinned KytyPS5 registrations](https://github.com/KytyPS5/KytyPS5/blob/f186b35706ddbc3faf5513f326e2335d224802f7/src/libs/libJson2.cpp#L1072),
selected through the immutable provider's literal export NID. They are not
formatted internal enum names, guest strings or guesses from call order.

Current source identity, owner, continuation, exact marker site, full service
ID and live immutable code/table attestation must all pass before attribution.
Guard refusals have no JSON label. Every new request clears the previous label;
successful JSON calls retain their existing `other-provider` profiling bucket.
The private allocator terminal site has no public export and no label.

The bounded diagnostic lookup allocates nothing and performs no guest-memory
read, callback, formatting or I/O. It does not alter the original error, result,
budgets, execution authority, bindings or protocol fields. No argument, address,
raw byte or NID is added to output. Earlier records lacking this attribution
cannot be retrospectively assigned a function from a generic failure category.

Original source fixtures exercise authenticated body failures, subsequent
success, stale-name clearing on forged requests, permission/byte tampering and
private-site refusal. A native imported constructor targets its original
consumer's own RX page to check real write refusal and the public label in both
supported exact scope pairs. Execution of those fixtures is a separate check;
their presence alone establishes no runtime or title result.
